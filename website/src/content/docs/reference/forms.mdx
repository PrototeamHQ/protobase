A public form creates a record of a resource for anyone, signed in or not: a contact form, a quote request, a sign-up for an event. `.form(...)` on the resource's view declares it, and the [anonymous role](/reference/access/#anonymous-access) grants `create` of its fields. Visitors never read the records back, and the form is the only way an anonymous caller creates.

`.form({ name, fields, thanks, title?, perMinute? })` takes:

| | |
| --- | --- |
| `name` | Its address, `/-/forms/<name>`: lowercase letters, digits, `-` and `_`, unique across the app. |
| `fields` | The fields a visitor fills in, in order. |
| `thanks` | What the page shows once the form is sent. |
| `title` | The page's heading; the view's singular name by default. |
| `perMinute` | How many submissions one client may send per minute; 5 by default. |

Each call adds a form, so a view can have several.

## What the visitor sees

`/-/forms/<name>` in the admin app shows the form's title over a card with its fields, labelled, with their help and checks as the view gives them, and a **Send** button. It needs no sign-in and opens the same for someone who is signed in; link to it from your website. On **Send** the browser solves the bot check, about a second of work, then sends the form; the card then shows the `thanks` text. A field the server refuses shows its problem under the field, and any other refusal, such as too many submissions, shows above the button with what was typed kept.

## What a form accepts

A form takes plain fields: text, numbers, booleans, dates, enums, currencies and countries. The server refuses to start on a form with:

- a relation, since a visitor cannot read the records to pick one;
- a file field, since a visitor cannot upload;
- a sensitive field that is not encrypted, a read-only or a generated field;
- a field the anonymous role's `<resource>.create` does not list; the error names the entry to add;
- a field the resource does not have, or two forms of the same name;
- a field every create must give left out, since no submission could then be saved.

An [encrypted field](/reference/data-config/#encrypted-fields) is written blind, masked as the visitor types, and stored encrypted.

## The record

A submission is a create like any other, made by the anonymous role and limited to the form's fields: the resource's `.validate()` rules, record rules and write hooks run, and [events](/reference/events/), [webhooks](/reference/webhooks/) and [history](/reference/history/) see it. History names its maker **Visitor**.

### Email me on a new submission

There is no mail built into forms: the record's `created` event enqueues a [job](/reference/jobs/), and the job [sends the mail](/reference/jobs/#mail).

## Rate limit

Each client may send a form `perMinute` times a minute, 5 by default, as many as it may try to sign in. Past that, the form answers `429` with `Retry-After`. A client is known by its address, as the sign-in limit knows it: see [Client addresses](/reference/auth/#client-addresses), and `PROTOBASE_TRUSTED_PROXIES` behind a proxy. The count is kept in each server process's memory, so with several instances each counts on its own, and a restart starts over.

## Bot check

Every submission carries a solved proof-of-work challenge ([ALTCHA](https://altcha.org)): the browser fetches a fresh one when the visitor presses **Send** and counts SHA-256 hashes until it finds the one the challenge asks for, about a second on a current laptop. There is no third-party service, cookie or visible puzzle, and it works offline. Sending many forms costs a bot that second each time, on top of the rate limit.

A challenge is made for one form, expires after 5 minutes and verifies once. The server signs challenges with `PROTOBASE_FORMS_SECRET`, or `BETTER_AUTH_SECRET` when it is not set, and does not start with a form and neither variable, so give every instance of an app the same one. The browser solves the check with Web Crypto, which needs `https` or `localhost`.

## Routes

The form's page reads and sends it through three routes beside the API, which need no token:

| Route | |
| --- | --- |
| `GET /api/forms/<name>` | `{ name, title?, fields, thanks, resource, view }`: the resource restricted to the form's fields and the view's hints for them, as `/api/meta` gives them; `404` for a form that does not exist. |
| `GET /api/forms/<name>:challenge` | A fresh bot check. |
| `POST /api/forms/<name>` | `{ values, proof: { challenge, solution } }` creates the record: `204`, or the `400` with field errors a create answers; `400` `bot-check-failed` for a missing, wrong, expired or used check; `429` `too-many-submissions`. |

From code, [`@protobase/client`](/reference/client/) has `form(name)`, `formChallenge(name)` and `submitForm(name, values, proof)`; solve the challenge with `solveChallenge` from `altcha-lib`, as the page does.
