You turn notifications on, send one when something happens in your app, and see it in the bell and as push on your browser. This guide uses the ERP example (`tests/apps/erp`, set up as its README says, with a user from `protobase users create`): when an order's status changes, its owner hears about it. The [Notifications reference](/reference/notifications/) has every option.

## 1. Turn notifications on

Add `notifications` to `protobase.config.ts`:

```ts
import { defineConfig } from '@protobase/config'

export default defineConfig({
  notifications: {},
  // auth, jobs, ...
})
```

Then write the tables it needs as a migration of your own, and apply it:

```sh
bun run protobase migration   # writes db/migrations/NNN_notifications.sql
bun run db:migrate
```

`protobase dev` refuses to start until the [devices and history tables](/reference/notifications/#table-names) are there.

## 2. Generate the Web Push keys

Browsers receive push through [Web Push](/reference/notifications/#web-push), which needs a key pair of your own:

```sh
bun run protobase notifications vapid-keys
```

Paste the two lines it prints into `.env`, and add how push services can reach you:

```sh
PROTOBASE_VAPID_PUBLIC_KEY=...
PROTOBASE_VAPID_PRIVATE_KEY=...
PROTOBASE_VAPID_SUBJECT=mailto:you@example.com
```

Keep the private key out of the repository. Without the keys, notifications still reach the bell, and browsers get no push.

## 3. Send one when a record changes

Declare the [event](/reference/events/#declaring-events) on the orders, in `config/orders/data.ts`:

```ts
  .events((e, r) => [e.updated('statusChanged', { changed: [r.status] })])
```

Then add a [subscription](/reference/webhooks/#subscription) that [sends a notification](/reference/notifications/#sending) to the order's owner, with a link to the order, and export it from `config/index.ts` beside the resources:

<Code code={orderStatus} lang="ts" title="config/orders/notifications.ts" />

```ts
// config/index.ts
export { orderStatusToOwner } from './orders/notifications'
```

`inbox: true` keeps it in the owner's [history](/reference/notifications/#history), which the bell shows, besides pushing it; `inbox: false` only pushes it. The same `sendNotification` works from a [job](/reference/jobs/), a write hook or an [API function](/guides/api-functions/).

The event needs triggers on the orders table, so write and apply the migration again:

```sh
bun run protobase migration   # writes db/migrations/NNN_changes.sql
bun run db:migrate
```

## 4. Turn push on from the bell

Run `bun run protobase dev`, open `http://localhost:5173` in a desktop browser and sign in. The [bell](/reference/notifications/#the-bell) in the top bar opens your notifications; at its foot, **Turn on** asks the browser for permission and registers this browser as one of your [devices](/reference/notifications/#devices). The panel then says that notifications are on for this device.

## 5. See it arrive

Make yourself the owner of an order, then change its status, in the app or with SQL: both count, since the change is captured in the database. Within a few seconds:

- the browser shows a notification such as "Order SO-2024-000245 changed status", and a click on it opens the order;
- the bell shows one unread notification, and opening it marks it read.

Every send is a background job: a failed one is on the [failed jobs page](/reference/jobs/#failed-jobs-page), and the server log has a line per delivery of the subscription.

On an iPhone or iPad, push reaches the app once it is added to the Home Screen, not a browser tab. Push to the Android and iOS builds of your app is coming soon; the [mobile guide](/guides/mobile-app/) builds them.

## 6. Turn the bell off or replace a part

- `notifications: { ui: false }` keeps sending, the history and devices, and draws no bell: your own UI reads the history and turns push on with [the browser helper](/reference/notifications/#in-the-browser) ([without the bell](/reference/notifications/#without-the-bell)).
- `shell.bell` in `protobase.ui.tsx` draws your own bell in its place ([the bell's slot](/reference/notifications/#the-bells-slot)).
- Your own device store, history store or senders replace the built-in ones, such as a store outside the database ([your own parts](/reference/notifications/#your-own-parts)).
- The tables' schema, names and columns can be renamed ([table names](/reference/notifications/#table-names)).
