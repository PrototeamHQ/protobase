A **subscription** delivers the [events](/reference/events/) of resources as they happen: to a URL, to one of the app's [API functions](/guides/api-functions/), or to code of its own. Subscriptions are config: export them from `config/index.ts` like resources, so the server has them and the admin UI never does. A URL or secret usually comes from the environment.

## subscription()

`subscription(name, options)`: the name is unique across the app and its [extensions](/reference/config/#extensions), and starts with a letter followed by letters, digits, `_` and `-`. Each has one target:

| Target | |
| --- | --- |
| `url` | A `POST` of the event as JSON. 2xx is a success; anything else, a redirect too, is a failure. The receiver has 15 seconds. |
| `function` | One of the app's API functions, called in this process with the same request a URL gets. |
| `run` | `(event, { db, attempt, signal }) => ...`, run for each event; it throws to fail the try. |

| Option | |
| --- | --- |
| `events` | Event names (`orders.created`), every event of a resource (`orders.*`), or all of them (`*`). Each must match a declared event. |
| `when` | A filter on the record after the change, or before it for a delete, in the language of access rules. |
| `as: { roles }` | Delivers as these roles: only records they may read, and only fields they may read. Without it, every record and every field but the sensitive ones. Their access rules cannot read a sensitive field, which a captured change does not hold: a change they would need one for is kept as failed. Check the role before such a field, as in `ctx.user.roles.includes('admin') \|\| record.api_secret == null`, or decide on a field that is not sensitive (see [Sensitive fields](/reference/data-config/#sensitive-fields)). |
| `tenant` | Only events of this tenant's records, on resources with `.tenant()`; a resource without one is not tenant-scoped, so its events reach every tenant's subscriptions that may read them. |
| `payload` | `thin` leaves `after` and `before` out, for a receiver that reads the record through the API. Default `full`. |
| `ordered` | One delivery at a time per record, in commit order. Default false. |
| `enabled` | Default true; `false` keeps the subscription in the config without delivering. |
| `secret` | `whsec_` and base64: signs the requests of a URL or function target. Without it they are unsigned. `newWebhookSecret()` makes one. An array of secrets signs with each of them, for a rotation. |
| `headers` | Extra request headers, such as an API key the receiver wants. |
| `body` | `(event) => ...`: what is sent instead of the event, such as Slack's `{ text }`. |

The server does not start while a subscription names an event no resource declares, has a `when` that does not check against a resource it covers, calls a function the app lacks, or is enabled with an empty URL.

## What a receiver gets

```http
POST /hooks/protobase
content-type: application/json
webhook-id: evt_48211_large
webhook-timestamp: 1791666245
webhook-signature: v1,K5oZfzN95Z9UVu1EsfQmfVNQhnkZ2pj9o9NDN/H/pI4=

{ "id": "evt_48211_large", "type": "orders.large", "timestamp": "2026-10-10T21:04:05.123Z",
  "data": { "resource": "orders", "operation": "update", "key": "7", "sequence": "48211",
            "after": { ... }, "before": { ... }, "changed": ["total"], "tenant": 1,
            "actor": { "id": "u_12", "roles": ["sales"] }, "source": "api", "transaction": "753" } }
```

- **`webhook-id`** is the same on every retry: a receiver that keeps the ids it handled ignores a second copy.
- **The signature** follows [Standard Webhooks](https://www.standardwebhooks.com): an HMAC-SHA256 of `id.timestamp.body` with the secret. A Protobase function checks it with [`verifyStandardWebhook`](/guides/api-functions/), and the Standard Webhooks libraries do the same elsewhere.
- **Records** use field names and values as `GET /orders/{key}` returns them, never sensitive fields. `changed` lists sensitive fields that changed, by name only.
- **`sequence`** grows with every change of a record, so a receiver can drop an event older than one it already has.
- **`actor`** is the caller of a write through the API, `null` for any other write (`source: "database"`).

A function target is called as the subscription's `as`, so `context.caller()` and its records are those roles; without `as`, as a caller without roles.

## Delivery and retries

- **The first try** goes out from the dispatch job, right after the write: within milliseconds for a write through the API, within two seconds for one from elsewhere.
- **A failed try** becomes a `webhooks.deliver` job, retried on the Standard Webhooks schedule with up to 10% jitter: 5 s, 5 m, 30 m, 2 h, 5 h, 10 h, 14 h, 20 h and 24 h, 10 tries over about three days. A `Retry-After` header makes the wait longer, up to a day.
- **`410 Gone`** fails the delivery at once.
- **After the last try** the job is kept as failed, on the [failed jobs page](/reference/jobs/#failed-jobs-page), where it can be retried.
- **Ordered subscriptions** get no first try from the dispatch job: a `webhooks.deliver-ordered` job delivers a record's events of one dispatch in order, retried with doubling waits from 5 s up to a day, 10 tries. Meanwhile the record's later events to that subscription wait. A retry sends again the events of that job that went through before the one that failed.
- **Every retry and resend follows the subscription as it is now:** its event leaves out fields that became sensitive since it was first made, and a subscription with `as` roles that may no longer read the record gets nothing. <gap>A retry of a thin event cannot check the row rules of `as` roles again because reading the current record for it is not implemented.</gap>
- **At least once:** a process that stops after delivering but before recording it delivers again when the dispatch job is retried, under the same `webhook-id`.
- **Event code that throws**, such as a `match` that reads a field it did not expect to be empty, a subscription's `when` or an access rule of its `as` roles, keeps that change as a failed `webhooks.dispatch-change` job on the failed jobs page, naming the event or subscription and the error, and dispatch moves on to later changes. Retry it once the code is fixed to deliver the change's events. An access rule of `as` roles keeps the change as failed for that subscription only: the other subscriptions still receive it, and the retry delivers it to that subscription alone. A database error instead fails the whole dispatch job, which is retried.

Every outcome is a line in the server log, such as `webhook newOrdersToSlack orders.created evt_48211_created delivered (200)`.

## Subscriptions in the admin app

A subscription in the config suits a developer. For people who make their own at runtime, such as a tenant admin wiring their organization to a tool they use, turn them on with `webhooks` in `protobase.config.ts`:

```ts
import { defineConfig } from '@protobase/config'

export default defineConfig({ webhooks: {} })
```

It adds two pages, over a `webhooks` schema that [`protobase migration`](/reference/cli/#migration) writes (`NNN_webhooks.sql`):

- **Webhook subscriptions** (`webhook_subscriptions`, the table `webhooks.subscriptions`): a name, the events (`orders.created orders.large`, or `orders.*`), the URL, a filter, extra headers, full or thin payload, and whether it is enabled. The server sets the tenant and the owner, the person who made it, and makes the secret, which only a [reveal](/reference/api/#sensitive-fields-and-audit) shows. Saving checks the events and the filter against the resources, and refuses a URL whose host is a private, loopback or link-local address.
- **Webhook deliveries** (`webhook_deliveries`, a view over the delivery jobs): the deliveries that wait for their next try or failed for good, with their last error. A delivery leaves the list once it succeeds.

The migration gives the subscriptions table an index for each sort, filter and search of its list, and creates the `pg_trgm` extension the search's indexes need (`create extension if not exists pg_trgm`, a trusted extension since Postgres 13, so any role that may create in the database can). A database that has an earlier version's schema gets the indexes from the next `protobase migration`; the server does not start until it is applied.

Both are scoped to the tenant like any resource with `.tenant()`, and their access decides who may do what: `webhook_subscriptions.create`, `webhook_deliveries.update` and so on, as for the app's own resources. A role's wildcard over resources, such as `*.read`, grants none of them: their URLs and secrets let whoever reads them call the receivers, so with roles only admins (`*`) and roles that [name them](/reference/access/#resources-that-need-named-grants) manage webhook subscriptions.

A subscription made here **delivers as its owner**, with the role they act with now in its tenant (the [active role](/reference/auth/#active-role) they last chose, else their first): only records and fields it may read. Letting people make subscriptions therefore grants them nothing they could not read already. The roles are read from the app's sign-in; a project that signs people in otherwise exports its own, `async ({ id, tenant }) => [...]`, as the default of `webhooks/owner-roles.ts`.

| Action | |
| --- | --- |
| Send test event | Sends the first event the subscription takes, made up from the newest record it may read, with `"test": true`. |
| Resend failed | Tries each delivery that failed for good once more. Webhook deliveries has the same for one delivery. |
| Rotate secret | Makes a new secret. For 24 hours requests carry a signature with each, so the receiver can switch over. |
| Disable | Stops its deliveries; waiting ones fail when their turn comes. Enabling it again starts afresh. |

A subscription is **disabled by itself** when its receiver answers `410 Gone`, or when no delivery succeeded for three days; the page says why.

| `webhooks` | |
| --- | --- |
| `schema` | The schema of its tables, for a database that has a `webhooks` schema already. Default `webhooks`. |
| `deliveryLog` | Also keeps every try, successes too, for 30 days, listed as Webhook delivery log: status, try, status code, for a failed try the error with up to 200 characters of the answer, and how long it took. Default false. |
| `allowPrivateAddresses` | Lets URLs reach private addresses, for development and tests. Default false. |
